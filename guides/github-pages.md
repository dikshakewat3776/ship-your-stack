# React/Vite Static Site on GitHub Pages

This guide covers a practical deployment flow for a static frontend app (React/Vite-style) hosted on GitHub Pages.

---

## Architecture

| Piece | Platform | Role |
|------|----------|------|
| Frontend | GitHub Pages | Serves static files generated by your build |
| Source control | GitHub | Stores source branch and deployment branch |

---

## 1) Prerequisites

- A GitHub repository with your frontend code.
- A production build command (for example, `npm run build`).
- A deployment command that publishes build output (for example, with `gh-pages`).

Optional but recommended:

- Lint/type checks before publishing.
- A custom domain only after the default Pages URL is working.

---

## 2) Configure Build for Repository Hosting

For project pages (`https://<user>.github.io/<repo>/`), ensure your app uses the correct base/public path.

For Vite, that usually means setting:

- `base: '/<repo>/'` in `vite.config.*`

If your site is a user/org page repo (`<user>.github.io`), base is typically `/`.

---

## 3) Validate Locally Before Deploy

- Install dependencies.
- Run lint/type checks.
- Run production build.
- Preview the built output locally and confirm routes, links, and assets load correctly.

---

## 4) Publish to GitHub Pages

A common approach is publishing the `dist` folder to `gh-pages`.

Typical scripts in `package.json`:

```json
{
  "scripts": {
    "build": "vite build",
    "deploy": "gh-pages -d dist"
  }
}
```

Then deploy:

```bash
npm run build
npm run deploy
```

In repository settings, configure Pages source as:

- **Branch:** deployment branch (commonly `gh-pages`)
- **Folder:** `/ (root)`

---

## 5) Verify Production

Open your Pages URL and validate:

- Homepage loads
- Client-side navigation works
- Hard refresh works for your router strategy
- JS/CSS/images are not broken by path issues

---

## 6) Ongoing Update Flow

- Make changes locally.
- Re-run quality checks.
- Commit and push source changes.
- Re-run deploy publish command.
- Re-verify the live URL.

---

## 7) Common Failure Points

- Wrong `base`/public path for repo-hosted URLs.
- Pages source branch/folder misconfigured.
- Deploying stale or incorrect build output.
- Browser cache showing old files after deploy.
- Using BrowserRouter without proper fallback strategy on static hosting.

---

## 8) Rollback Strategy

- Re-deploy the last known good commit/tag.
- Publish again to the Pages branch.
- Recheck the live URL after propagation.

---

## Quick Verification

1. `npm run build` passes locally.
2. GitHub Pages URL loads without 404/blank page issues.
3. Deep links and static assets resolve correctly.
